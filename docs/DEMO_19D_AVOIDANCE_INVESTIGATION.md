# 데모 & 19D 회피 학습 조사 기록 (2026-06-02)

멀티로봇 창고 데모(선반 회피 + 박스 운반 + S1~S6 시나리오)를 만들기 위한 긴 디버깅 세션의
전체 기록. 무엇이 문제였고, 무엇을 고쳤고, **아직 안 풀린 근본 문제와 권장 경로**를 정리한다.

> 작업 브랜치: `diff-drive-finetune`. 데모 외형 작업은 `main`.

---

## 0. 목표

`demo_play.py`로 **로봇 3대가 선반(정적 장애물)을 피하고, 서로 협응하며, S1~S6 시나리오대로
일하는** 영상. 사용자 핵심 요구: "선반에 박거나 멀뚱히 서있지(방향 못 찾지) 않는다."

---

## 1. TL;DR (현재 결론)

- **데모 인프라(카메라/시나리오 재생/외형/시각)는 다 고쳐졌다.** 아래 §2.
- **17D 정책(model_10998)은 로봇간 회피·협응은 잘하나(0% 충돌, S1 83%·S2 96%) 선반 회피는
  구조적으로 불가**(obs에 선반 "거리"만 있고 "방향" 없음). §3.
- **19D(방향 obs) 학습은 아직 성공 못 함.** 정규화 버그·warm-start·선반 보상까지 고쳤지만,
  **학습/평가 분포 불일치**라는 근본 벽에 막혀 있다. §4~§5.
- **다음 정공법: "시나리오형 학습"** — eval가 테스트하는 상황(정면교행·3way·선반교차)을
  학습 데이터에 직접 넣는 것. 랜덤 목표로는 그 상황을 안 겪어 영영 못 배운다. §6.

## 2. 데모 인프라에서 고친 것들 (해결됨)

`demo_play.py`에서 순서대로 발견·수정:

| 증상 | 원인 | 수정 |
|---|---|---|
| 로봇이 제자리서 빙빙, 목표 옆서 정지 | `--diff_drive_ctrl`: `vx=속도·relu(cos(목표각오차))` → 목표가 옆/뒤면 전진=0, 회전만 | 시나리오 데모 기본을 `--visual_yaw_align`(완전 홀로노믹 주행 + 외형만 회전)로 |
| 화면이 하얗게 날아감 | 부감 카메라(z=13.5)가 창고 USD **지붕** 위로 나감 | 시나리오 모드는 바닥판만(ground plane) |
| 로봇이 화면 구석/안 보임 | 카메라가 옛 운반데모용(아래 선반 y≈-2.5 조준) | 시나리오 전용 중앙 부감 카메라(`SCN_CAMERA`) 자동 |
| 목표 근처서 완전 정지("좀비") | (1차 가설) PhysX 슬립 — 무관으로 판명, 무해하게 둠 | `sleep_threshold=0` (무해) |
| 스폰 Y가 -3 밀려 랙에 박힘 | `_scn_apply(0)`를 `__init__`(시뮬 시작 전)에 호출 → 물리 초기화가 텔레포트 덮어씀 | 첫 배치를 첫 스텝(스텝 중)으로 이연 |
| "지금 무슨 시나리오?" 구분 불가 | demo는 시나리오 없는 랜덤 픽업↔도크 맴돌기였음 | `--scenario_demo`: S1~S6형 4종 순차 재생 + 콘솔 배너 + 색 골마커 + 자막 스케줄 tsv |
| 매 시나리오 1대가 랙에 박힘 | 17D 한계(§3) | (땜질) 시나리오 모드 랙 충돌 OFF — 이후 정공법으로 선회 |

추론 정규화 처리도 수정: `eval_scenarios`/`demo_play`가 체크포인트의 정규화 버퍼를
자동 탐색·적용하도록(키 이름 무관). §4 참고.

## 3. 17D 정책의 구조적 한계

- `model_10998.pt`, `model_9999.pt` = **17D** (actor 입력 17). 사용 가능한 유일한 멀티로봇 정책.
- 17D obs의 선반 정보 = **`shelf_dist` 스칼라 1개**(거리만). **방향 없음.**
- → 목표가 선반 뒤/옆이면 어디로 틀지 정보가 없어 **박거나 멈춤**. 튜닝으로 못 고침.
- **baseline eval (model_10998, 100 ep):**

| 시나리오 | 충돌 | 교착 | 도달 | 비고 |
|---|---|---|---|---|
| S1 교행 | 0% | 17% | 83% | |
| S2 3way | 0% | 4% | 96% | |
| S3 배터리 | 0% | 98% | 2% | 배터리 obs 없음(불공정) |
| S4 동일목표 | 0% | 100% | 0% | 두 로봇 같은 점 = 정의상 동시도달 불가 |
| S5 혼잡(선반) | 0% | 16% | 84% | **선반 환경 — 16% 교착이 박힘/멈춤** |
| S6 장애물 | 0% | 5% | 95% | `--enable_obstacles` 없어 장애물 미출현(무의미) |

- **충돌(로봇간) 0%는 우수.** 약점은 S5의 16% 교착(=선반 박힘/멈춤)과 S6 동적 회피(미검증).
- 데모가 결정론적 고정 스폰이라 eval의 84%보다 더 자주 박혀 보였음(같은 나쁜 케이스 반복).

## 4. 19D 확장 obs 학습 — 시도와 버그

`--extended_obs` = obs 17→19D (가장 가까운 장애물 body-frame xy 추가). 학습은 `train_marl.py`,
저장 경로 `logs/warehouse_mappo_extobs/`.

### 4.1 정규화 버그 (해결)
- `empirical_normalization=True`로 학습 시 obs 정규화되나, eval/demo 추론이 정규화를 안 걸어
  생짜 obs 투입 → **즉시 100% 충돌**. 모델이 아니라 **추론 로더 버그**였음.
- rsl_rl은 `empirical_normalization`을 `actor/critic_obs_normalization`로 매핑, 정규화를
  policy 안에 둠 → `model_state_dict`에 저장. `eval_scenarios.load_policy`가 키를
  `actor_normalizer.running_mean`로 하드코딩해 못 찾던 것 → **이름 무관 자동 탐색**으로 수정.
- `demo_play`도 체크포인트에 정규화 버퍼 있으면 `empirical_normalization=True`로 policy 구성.

### 4.2 raw obs(정규화 OFF)는 학습 안 됨
- warm-start 규격 일치를 위해 정규화를 끄면 raw obs 스케일이 커서 **정책 그래디언트가 죽음**
  (std 0.8 고정, 학습 정지). → from_scratch는 정규화 필수. warm-start는 시작이 좋은 정책이라
  raw로도 미세조정은 됨.

### 4.3 제로패딩 warm-start (기법 성공)
- from_scratch 19D는 학습/평가 분포 불일치로 **공격적 충돌 정책에 수렴(퇴행)**.
- 대신 `--ippo_ckpt model_10998`의 입력층을 **버리지 않고 키움**: `actor.0.weight` 256×17→256×19,
  기존 17칸 복사 + 새 2칸 0초기화 → **시작 시점 = model_10998 그대로**(회피 보존).
- 결과: warm-start model_200이 **S1/S2 100%, 충돌 6%, 도달 68.7%** — 회피 보존 확인(기법 OK).
- **하지만 계속 학습하면 단조 퇴행**(200→400→600: 도달 68→59→46%). §5.

## 5. 선반 회피가 안 배워진 3대 원인 (코드로 수정함, 커밋 `2950c88`)

19D가 방향 obs를 받고도 선반 회피를 못 배운 진짜 이유:

1. **obs 결함**: `_nearest_obstacle_body`가 선반 **중심**을 가리킴. 선반은 3m 박스라 끝에 있는
   로봇이 엉뚱한 옆방향을 받아 벽 위치를 모름 → **AABB 가장 가까운 표면점**으로 교체.
2. **보상 부재**: 선반에 박아도 벌점 0(교착 시간낭비뿐). robot-robot은 `rew_collision −200`
   있으나 정적 선반은 없었음 → **`rew_shelf_prox`** 추가(표면 거리비례 −/step).
3. **상황 부재**: 목표가 `_goal_in_shelf` margin 0.8 리젝션으로 항상 트인 곳 → 선반 돌아갈 일
   없음 → **`goal_shelf_margin`** 노브로 선반 근처/뒤 목표 허용(우회 강제).

### 5.1 수정 후 학습 결과 (warm-start + 위 3수정, model_1200)
- 학습 자체는 건강(reward ~700 안정, std 0.76→0.67, 음수 추락 없음).
- **그러나 eval은 여전히 실패:**

| 시나리오 | 충돌 | 교착 | 도달 |
|---|---|---|---|
| S1 교행 | 0% | 7% | 93% (양호) |
| **S2 3way** | **100%** | 0% | 0% (로봇 회피 깨짐) |
| S5 혼잡(선반) | 0% | **37%** | 63% (**baseline 16%보다 악화** = 과회피) |

- **S5 교착↑** = 선반 벌점이 너무 세서 **과회피(선반 무서워 통로 못 지나 정지)**. 박음→멈춤으로 치환.
- **S2 100% 충돌** = 학습 중 3way 정면대치를 안 겪어 못 배움(분포 불일치).

## 6. 남은 근본 문제 & 권장 경로

### 진단 (확정)
**랜덤 목표로 학습하는 한, eval 시나리오(정면교행·3way·선반교차)를 안정적으로 못 한다.**
학습이 그 상황을 거의 안 만들기 때문(robots가 흩어진 목표로 가며 충돌·선반 거의 안 겪음).
- S2 충돌: 학습 reward는 +700(안 죽음)인데 eval S2는 5스텝 충돌 = **안 겪은 상황은 못 배움.**
- 보상 튜닝(선반 벌점 등)으로는 이 벽을 못 뚫는다. obs/벌점/목표를 다 고쳐도 "무엇을 학습하나
  (상황)"가 빠졌음.

### 권장 정공법: 시나리오형 학습
랜덤 목표 대신 **정면교행·3way·선반교차 같은 시나리오형 스폰/목표를 랜덤화해서 학습** —
모델이 "시험에 나오는 상황"을 연습하게. 학습 reset 로직(`_reset_idx`/goal 샘플링)을 바꾸는
실제 작업이며, ML이라 **eval 숫자(특히 S5 교착·S2 충돌)로 검증되기 전엔 성공 단언 금지.**

### 대안 (타협)
17D `model_10998`은 로봇간 회피·협응은 검증됨(S1 83%·S2 96%·충돌 0%). 선반은 ~84%(완벽X).
선반 회피를 포기하고 **협응 데모**만 원하면 17D + `--scenario_demo`로 오늘도 가능. 단 사용자
핵심 요구(선반 박힘 제거)는 미해결.

## 7. 핵심 측정 비교표 (S5 교착 = 선반 회피 단일 지표)

| 모델 | S1 도달 | S2 | S5 교착(선반) | 평가 |
|---|---|---|---|---|
| 17D baseline (model_10998) | 83% | 96% 도달 | **16%** | 현재 최고의 "전반 안정" 모델 |
| 19D from_scratch (norm 버그) | — | — | — | eval 100% 충돌(로더 버그) |
| 19D from_scratch (수정 후) | 100%→붕괴 | 100% 충돌 | 100% | 퇴행, 공격적 충돌 |
| 19D warm-start (선반수정 전) model_200 | 100% | 100% 도달 | 23% | 회피 보존 OK, 선반 개선 X |
| 19D warm-start + 선반수정 model_1200 | 93% | 100% 충돌 | **37%** | 과회피+S2붕괴, 미해결 |

목표: **S5 교착 < 10% + S1/S2 도달 90%+ + 충돌 ~0%** 동시 달성. 아직 못 함.

## 8. 파일 & 명령어 레퍼런스

- 데모: `python training/multi_robot/demo_play.py --scenario_demo --checkpoint <ckpt> [--extended_obs] --video --headless`
  - 19D 모델이면 `--extended_obs` 필수. 시나리오 모드면 `--visual_yaw_align` 자동.
- 평가: `python training/multi_robot/eval_scenarios.py --ckpt <ckpt> [--extended_obs] --num_episodes 100 --num_eval_envs 16 --tag <tag> --headless`
- 학습(현 시점 최선 시도): `python training/multi_robot/train_marl.py --ippo_ckpt logs/warehouse_mappo/model_10998.pt --extended_obs --no_obs_norm --rew_evasive_turn 0.3 --rew_clearance 0.15 --rew_shelf_prox -1.5 --goal_shelf_margin 0.6 --num_envs 256 --headless`
  - 단 §5.1대로 미해결. §6의 시나리오형 학습이 다음 단계.
- 핵심 노브(`WarehouseMARLEnvCfg`): `extended_obstacle_obs`, `rew_evasive_turn`, `rew_clearance`,
  `rew_shelf_prox`, `shelf_prox_dist`, `goal_shelf_margin`.

## 9. 교훈

- **"무엇을 학습하나(데이터 분포) > 어떻게 보상하나"** — eval에 안 나오는 상황은 못 배운다.
- 모델 능력은 **eval 숫자로 검증** 후에만 "된다"고 말한다. 학습 reward(대리 지표)로 판단 금지.
- 못 하는 모델 위에 데모 화면만 칠하는 땜질은 반복 실패한다. 모델부터 숫자로 세운다.
