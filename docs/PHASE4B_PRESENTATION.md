# MARS 발표 자료 — 대본 + 아키텍처 (10분 / 10장)

창고 멀티로봇 시스템 MARS. 두 레이어 — **RL 제어**(로봇 능력) + **멀티에이전트 오케스트레이션**(함대 두뇌) — 를 각각 시연하고, 둘을 잇는 것이 목표임을 보인다.

- 분량: 10장 / 약 10분 (영상 4개 ≈ 3분, 말 ≈ 7분)
- 정직 원칙: demo1 = "에이전트 ↔ 내비게이션 통신이 실제로 동작"(O) / "RL을 에이전트가 직접 구동"(X, 로드맵)
- 산출물(이미 확보): `demo1_keepout.mp4`, `demo2_charging.mp4`, `demo3_priority.mp4`, `agent_conversation.txt`, `demo{1,2,3}_log.txt`

---

## 1. 아키텍처 다이어그램 A — 2-레이어 개요 (슬라이드 2용)

새로 그려야 하는 그림 1. 박스 2개 + 양방향 화살표, RL↔에이전트 직결만 점선(미실현).

```
┌──────────────────────────────────────────────────────────────────┐
│        SUPERVISORY MULTI-AGENT LAYER  (함대 두뇌)                   │
│                                                                    │
│   FailureAnalysis  ⇄  OperationsStrategy  ⇄  FleetState            │
│        (LLM, Haiku, ReAct)        (LLM)         (LLM)              │
│   + DecisionValidator · Guardrail · PolicyManager  (결정론 안전)    │
│                                                                    │
│   → 함대 차원 결정: avoid_zone(구역 차단) / 충전 우선순위·교대      │
└───────────────▲──────────────────────────────┬───────────────────┘
                │                               │
   robot state / failures (상태·실패 보고)      │  policy / commands (정책·명령 하달)
                │                               ▼
┌───────────────┴──────────────────────────────────────────────────┐
│        ROBOT CONTROL LAYER  (로봇 능력)                            │
│                                                                    │
│   Navigation (Nav2)              RL policies (학습된 제어)          │
│   [데모 시연: 실제 구동]   ·····  [데모 시연: 별도]                 │
│                                                                    │
│   ┄┄┄ RL 정책을 제어 슬롯에 통합 = 로드맵(점선) ┄┄┄                │
└──────────────────────────────────────────────────────────────────┘
```

**그릴 때 포인트**
- 위 박스 = 두뇌(파랑 계열), 아래 박스 = 로봇(회색 계열).
- 가운데 화살표 2개: 왼쪽 위로 "상태/실패 보고", 오른쪽 아래로 "정책/명령 하달". → **이게 오케스트레이션 ↔ 로봇 통신(demo1에서 실제 동작).**
- 아래 박스 안에서 Nav2와 RL을 나란히, 그 사이 **점선**으로 "통합=목표". (지금은 데모의 컨트롤러가 Nav2/follower고 RL은 별도라는 걸 점선이 정직하게 표현.)

## 2. 아키텍처 다이어그램 B — 오케스트레이션 파이프라인 (슬라이드 6용)

새로 그려야 하는 그림 2. 실패 → 에이전트 루프 → 정책 → 로봇. 가운데 블랙보드(공유 DB)가 에이전트 간 통신 매개.

```
        robot failure (Nav2 abort, 예: 통로 막힘)
                    │
                    ▼
        ┌────────────────────────┐        ┌──────────────────────┐
        │  FailureAnalysisAgent  │◄──────►│   Blackboard (공유 DB) │
        │  (Haiku, ReAct)        │ 읽기:  │  failures, diagnoses, │
        │                        │ query_failures /            │  policies, incidents  │
        │                        │ get_zone_state /            │  (에이전트 간 통신·  │
        │                        │ search_incidents(RAG)       │   시간 너머 통신)    │
        └───────────┬────────────┘        └──────────────────────┘
                    │ diagnosis {cause, scope, confidence}
                    ▼
        ┌────────────────────────┐
        │   DecisionValidator    │  grounding / confidence gate
        └───────────┬────────────┘  PASS
                    ▼
        ┌────────────────────────┐
        │ OperationsStrategyAgent│ → POLICY_WHITELIST에서 정책 선택
        │  (Haiku)               │   (avoid_zone, reserve_chargers_for_critical,
        └───────────┬────────────┘    delay_low_priority_missions, ...)
                    ▼
        ┌────────────────────────┐
        │      Guardrail         │  안전 거부 (예: 충전기 전부 예약 → 차단)
        └───────────┬────────────┘  ACCEPT
                    ▼
        ┌────────────────────────┐
        │     PolicyManager      │  정책 활성화
        └───────────┬────────────┘
                    │
        ┌───────────┴───────────────────────────────┐
        ▼                                           ▼
  KeepoutService                            ChargingService (우선순위 큐 + CAS)
  zone polygon → OccupancyGrid mask         critical-first / 교대 직렬화
  → /keepout_filter_mask (latched)          → 로봇별 디스패치
  → Nav2 KeepoutFilter (costmap)
  → 로봇 우회 (demo1)                        → 로봇 충전 순서 (demo2/3)
```

**그릴 때 포인트**
- 세로 흐름(실패→진단→검증→전략→가드레일→정책)을 한 줄로.
- **블랙보드**를 오른쪽에 두고 FailureAnalysis와 양방향 화살표 → "에이전트들이 공유 메모리로 통신(A2A)".
- 맨 아래에서 두 갈래(KeepoutService=demo1, ChargingService=demo2/3)로 분기.
- 색 구분: LLM 에이전트(파랑), 결정론 안전(Validator/Guardrail/PolicyManager, 주황) → "LLM + 안전 레이어" 대비가 보이게.

## 4. 예상 Q&A (정직 대응)

**Q. RL이랑 에이전트가 지금 직접 연결돼 있나요?**
A. 오케스트레이션 ↔ 로봇 내비게이션의 통신 루프(실패 보고 → 판단 → keepout → 우회)는 실제로 동작합니다(demo1). 다만 데모의 로봇 컨트롤러는 Nav2이고, RL 정책을 그 자리에 통합하는 것이 다음 단계입니다. 기술 경로는 명확하고(관측 정합 + keepout을 RL obs로), 안정성 검증이 남았습니다.

**Q. LLM이 실제로 결정하나요, 아니면 정해진 규칙인가요?**
A. 둘 다입니다. 진단·전략 추론은 LLM(에이전트 대화 로그가 라이브 호출 증거, zone_wide 0.85). 그 위에 결정론적 검증기·가드레일·우선순위 큐가 안전과 신뢰성을 보장합니다. LLM 단독이 아니라 "LLM 추론 + 안전 레이어"가 핵심이고, demo3에서 가드레일이 위험한 LLM 정책을 차단하는 게 그 예입니다.

**Q. sim-to-real은요?**
A. 본 연구의 기여는 함대 차원 감독 의사결정 레이어이고, 이 결정 로직은 로봇 제어와 분리(robot-agnostic)됩니다. 따라서 현실적 실패·충전·경합 모델을 갖춘 시뮬레이션에서 평가하며, 물리 함대 배치는 범위 밖(future work)입니다. 저수준 제어의 sim-to-real은 직교하는 문제입니다.

**Q. 스케일은?**
A. 현재 데모는 로봇 3대 규모의 시연이고, 정량 평가와 스케일업(로봇 수·시나리오·존/충전소 확대)은 진행 예정입니다. 결정 로직은 시뮬레이션(MockSim)에서 헤드리스로 다수 시드·시나리오를 돌릴 수 있어 평가가 가능합니다.
